# 프로젝트: Support Desk — 고객 문의 관리 대시보드

## 1. 프로젝트 목표

React 프론트엔드 개발자 취업 포트폴리오를 위한 고객 문의 관리 웹 애플리케이션을 개발한다.

단순한 정적 UI가 아니라 실제 서비스처럼 동작하는 관리자 시스템을 만든다. 검색, 필터링, 페이지네이션, CRUD, 상태 관리, API 통신, 통계 시각화 등을 구현한다.

나는 기존에 웹 퍼블리싱 업무를 해왔으며, Vue와 Nuxt를 사용한 경험이 있다. 이번 프로젝트에서는 React와 TypeScript를 실무 수준으로 학습하는 것이 목적이다.

따라서 코드를 작성할 때 기존 코드와 프로젝트 구조를 먼저 확인하고, 불필요한 파일이나 기능을 추가하지 않는다. 구현 이유와 핵심 개념을 한국어로 설명한다.

## 2. 기술 스택

- React
- TypeScript
- Vite
- SCSS
- React Router
- TanStack Query
- Recharts
- ESLint

필요한 라이브러리는 실제 사용 목적에 맞게 설치한다. 초기 단계부터 불필요한 라이브러리를 추가하지 않는다.

백엔드는 추후 별도 구현할 예정이므로 초기에는 모의 데이터를 사용한다. 이후 실제 REST API로 교체할 수 있도록 데이터 처리 로직과 UI를 분리한다.

## 3. 주요 기능

### A. 대시보드 홈

- 전체 문의 건수
- 미처리 문의 건수
- 처리 중 문의 건수
- 처리 완료 문의 건수
- 기간별 문의 발생 추이
- 상태별 문의 비율
- 최근 접수된 문의 목록

통계는 하드코딩된 숫자가 아니라 실제 문의 데이터로부터 계산한다.

### B. 문의 목록

- 문의 목록 테이블
- 문의 제목, 고객명, 문의 유형, 우선순위, 담당자, 접수일, 처리 상태 표시
- 제목 및 고객명 검색
- 처리 상태별 필터
- 문의 유형별 필터
- 우선순위별 필터
- 담당자별 필터
- 접수일 기준 정렬
- 페이지네이션
- 검색 결과가 없을 때의 빈 상태 UI

검색, 필터, 정렬, 페이지네이션은 서로 연동되도록 구현한다. 검색 조건이 변경되면 페이지를 첫 페이지로 초기화한다.

### C. 문의 상세

- 문의 상세 정보
- 고객 정보
- 문의 내용
- 처리 상태 변경
- 우선순위 변경
- 담당자 배정
- 답변 작성 및 수정
- 처리 이력 표시
- 문의 목록으로 돌아가기

### D. 문의 CRUD

- 신규 문의 등록
- 문의 수정
- 문의 삭제
- 필수 입력값 검증
- 저장 성공 및 실패 피드백
- 삭제 전 확인
- 데이터 변경 시 목록과 대시보드 통계 동기화

초기 버전에서는 브라우저를 새로고침해도 데이터가 유지되도록 적절한 로컬 저장 방식을 사용한다. 저장 로직은 나중에 서버 API로 교체할 수 있도록 분리한다.

### E. 담당자 관리

- 담당자 목록
- 담당자 이름 및 이메일
- 담당자별 배정 문의 수
- 담당자별 처리 현황

초기 버전에서는 모의 데이터를 사용한다.

## 4. 문의 데이터 모델

TypeScript 타입을 정의하고 일관되게 사용한다.

문의 데이터에는 다음 항목을 포함한다.

- id
- title
- customerName
- customerEmail
- category
- priority
- status
- assigneeId
- description
- answer
- createdAt
- updatedAt
- history

처리 상태는 다음과 같이 구분한다.

- OPEN: 미처리
- IN_PROGRESS: 처리 중
- RESOLVED: 처리 완료

우선순위는 다음과 같이 구분한다.

- LOW: 낮음
- MEDIUM: 보통
- HIGH: 높음
- URGENT: 긴급

화면에 표시하는 상태명과 우선순위는 한국어로 제공한다. 내부 데이터 값은 영문 상수로 관리한다.

문의 이력은 상태 변경, 담당자 변경, 답변 작성 등의 작업을 기록한다.

## 5. UI 및 디자인 방향

실제 SaaS 관리자 페이지처럼 깔끔하고 전문적인 디자인을 구현한다.

- 왼쪽 고정 사이드바
- 상단 헤더
- 메인 콘텐츠 영역
- 명확한 타이포그래피 계층
- 일관된 여백과 정렬
- 카드형 통계 영역
- 읽기 쉬운 데이터 테이블
- 상태별 구분이 명확한 배지
- 검색창과 필터 영역
- 모달 또는 적절한 상세 화면
- 로딩, 오류, 빈 데이터 상태
- 데스크톱을 우선으로 하되 태블릿과 모바일에서도 사용할 수 있는 반응형 레이아웃

SCSS를 활용해 스타일을 직접 구현한다. 반복되는 스타일은 공통 변수와 재사용 가능한 클래스 또는 컴포넌트로 관리한다.

과도한 애니메이션, 불필요한 장식, 의미 없는 차트는 피한다.

## 6. 코드 구조

기능과 책임에 따라 파일을 분리한다.

예상 구조:

```
src/
  app/
    App.tsx
    router.tsx
  components/
    layout/
    common/
    data-display/
    forms/
  features/
    dashboard/
    inquiries/
    agents/
  hooks/
  services/
  mocks/
  types/
  utils/
  styles/
    _variables.scss
    _mixins.scss
    global.scss
  main.tsx
```

실제 구조는 필요에 따라 조정하되, 작은 컴포넌트까지 무조건 별도 파일로 분리하지 않는다.

다음 원칙을 지킨다.

- UI 컴포넌트와 데이터 처리 로직 분리
- TypeScript의 any 사용 최소화
- 재사용 가능한 컴포넌트 설계
- Props와 이벤트 타입 명시
- 로딩 및 오류 처리
- 의미 있는 함수와 변수 이름 사용
- 중복 코드 최소화
- 접근성을 고려한 시맨틱 HTML과 키보드 조작 지원
- 불필요한 전역 상태 사용 금지

## 7. React 학습 목적

코드를 작성할 때 다음 내용을 특히 신경 쓴다.

- 컴포넌트 분리 기준
- Props와 상태의 차이
- useState와 useEffect의 올바른 사용
- useMemo와 useCallback이 실제로 필요한 경우
- 커스텀 Hook 설계
- 폼 상태 및 유효성 검사
- 서버 데이터와 UI 상태의 구분
- TanStack Query를 이용한 서버 데이터 관리
- React Router를 이용한 화면 이동
- TypeScript 타입 설계
- API 요청과 오류 처리

최적화 목적으로 불필요한 Hook을 남용하지 않는다. 각 기술을 적용한 이유를 설명한다.

## 8. 개발 진행 방식

한 번에 전체 프로젝트를 무작정 생성하지 않는다.

다음 순서로 진행한다.

1. 현재 작업 디렉터리와 기존 파일 확인
2. Node.js, npm 환경 및 프로젝트 존재 여부 확인
3. 프로젝트 구조와 개발 계획 설명
4. 필요한 패키지 설치 및 기본 환경 설정
5. 공통 레이아웃 구현
6. 문의 모의 데이터 및 TypeScript 타입 정의
7. 문의 목록과 검색·필터·페이지네이션 구현
8. 문의 상세 및 CRUD 구현
9. 대시보드 통계 구현
10. 담당자 관리 구현
11. 오류 처리 및 반응형 UI 개선
12. 빌드와 주요 기능 검증

각 단계가 끝날 때 다음 내용을 한국어로 알려준다.

- 변경한 파일
- 구현한 기능
- 주요 코드의 동작 원리
- 직접 확인해야 할 사항
- 발생한 오류와 해결 방법

가능한 경우 실제로 명령어를 실행하고 결과를 확인한다. 실행하지 않은 테스트를 통과했다고 주장하지 않는다.

## 9. 작업 규칙

- 기존 파일이 있다면 먼저 읽고 구조를 파악한다.
- 기존 작업을 임의로 삭제하거나 덮어쓰지 않는다.
- 사용하지 않는 라이브러리를 설치하지 않는다.
- 요구하지 않은 기능을 임의로 추가하지 않는다.
- 오류가 발생하면 원인을 확인한 뒤 수정한다.
- 모의 데이터와 실제 API를 구분한다.
- 환경변수에 비밀 정보를 직접 노출하지 않는다.
- 사용자 인증이나 권한 기능을 구현할 경우 보안상 한계를 명확히 한다.
- 한국어로 설명한다.
